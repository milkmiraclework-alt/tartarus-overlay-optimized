# Tartarus Overlay — оптимизированный локальный форк

Форк [Tartarus Simulator / CoffeeBns](https://github.com/blahdot3h/tartarus-simulator)
для быстрого получения подсказок в оверлее Torchlight: Infinite.
Версия: **0.2.20-local.27**, правила синхронизированы с
[исходником автора `308b947`](https://github.com/blahdot3h/tartarus-simulator/tree/308b9479bcd0857a581a7e7b7917d0a8e0c5062e).

## Что оптимизировано

В **local.27** перенесены новые вероятности и правила автора от 23 октября в JS и Rust,
обновлены оценки инструментов и исправлен перенос длительности Iron Law между забегами.
Старый кеш расчётов отделён от нового; подтверждённые инструменты сохраняются.
Перед снимком первые проверки стабильности читают только 1 536 выбранных пикселей через
маленькую поверхность 32×48. Поле и кнопки распознаются после стабилизации; принятый кадр
передаётся основному читателю вместе с результатом. Ранняя проверка включена и для коротких
переходов Speed-up. Первый сигнал появления карт после явного действия сохраняет его
проверку готовности, а новое действие отменяет прежний кадр.

Локальная сборка создаётся в `desktop/dist/builds/<версия>/`; штатный запуск выбирает
проверенную сборку через `local/tartarus/active-standalone.json`. Работающий старый оверлей
не перезаписывается: после обновления его нужно закрыть через трей и запустить заново.

- **Локальный оверлей.** Один фоновый обработчик анализа; настройки и исправление
  доски открываются по запросу. Запуск не требует открытого браузера.
- **Самостоятельный EXE.** Portable и установщик включают свой Electron,
  нативные библиотеки, анализатор, WASM и английский OCR. Движок и языковая
  модель распознавания больше не скачиваются из CDN при первом чтении.
  Установка оверлея автора не требуется; прежний профиль и кэш сохраняются.
- **Потоки под процессор.** Число рабочих потоков симуляции выбирается автоматически:
  доступные логические потоки минус один, от 1 до 16. Например, 4 → 3, 8 → 7,
  12 → 11, 24 → 16. Ограничение сдерживает число воркеров на многоядерных ПК;
  объём Монте-Карло сохраняется. Это правило распределения ресурсов, а не
  замер оптимального числа потоков для каждого процессора.
- **Передача кадров.** Картинка передаётся напрямую в распознавание через
  `ImageBitmap`. Промежуточные PNG и пересылка полноразмерных кадров между
  страницами убраны из этого пути. Неактуальные кадры и задания отменяются;
  необязательная запись скриншотов выполняется после выдачи подсказки.
- **Распознавание.** Общие проходы по пикселям, меньше временных объектов,
  2–4 постоянных вспомогательных воркера для поиска доски и чтения панелей.
  Геометрия доски проверяется и используется повторно; панель переиспользуется
  только при полном совпадении её пикселей. Заключённые и события читаются заново.
- **Rust/WebAssembly для пикселей.** Поиск положения поля и фильтрация изображения
  выполняются скомпилированными функциями; SIMD проверяет два положения одновременно,
  сохраняя порядок суммирования и исходные оценки. Rust для запуска не нужен;
  при недоступности WebAssembly работает прежний JavaScript. Проверка окончания
  анимации передаёт прочитанные клетки и кнопки основному обработчику для того же
  снимка. Другие снимки, иной язык и уменьшение 4K не используют эту передачу.
- **Монте-Карло на Rust.** Правила, полное проигрывание партий, стратегия,
  оценка цепочек, выбор инструментов и подарков работают внутри WebAssembly.
  Компактная доска копируется без журналов и объектов интерфейса; кэш цепочек
  ограничен по размеру. Между JS и Rust передаются исходная позиция и новые
  выборки, без обмена на каждом ходе симуляции. Полный бюджет расчёта сохранён,
  включая запасной JS-путь; досрочной остановки по таймеру нет.
- **Сборка для оверлея.** Убраны веб-симулятор, руководства, отправка отчётов
  и данных автору, опрос обновлений веб-страницы и бинарный автообновлятор автора.
  Исправление доски, настройки, локальный журнал и уведомления об изменениях
  исходника автора сохранены. Прямой режим не создаёт канал браузерной Follow-страницы.
  Автозапись каждой доски и снимков для диагностики отключается при обновлении;
  прежние записи не сканируются и не удаляются, запись можно включить вручную.
- **Кэш подсказок.** До 256 полных результатов, около 8 МиБ, срок хранения
  7 дней; сохраняется после перезапуска. Совпасть должны все входные данные,
  инструменты, правила и бюджет расчёта. Ручной Recheck пересчитывает заново.
- **Подготовка следующих ходов.** Фоновый расчёт до двух действий вперёд;
  горизонт продлевается после каждого подтверждённого хода. Используется
  только точное совпадение с реально прочитанной доской. Незавершённый подходящий
  расчёт продолжается с уже набранными выборками. Общая таблица патрулей
  переиспользуется для разных наборов доступных дверей.
- **Нагрузка вне режима.** При выходе с экрана тюрьмы останавливаются захват,
  распознавание, OCR и расчёты наперёд. Остаются наблюдение за логом и лёгкий
  поиск окна через Win32. Устаревшие асинхронные ответы не возобновляют работу.
- **Меньше повторных подтверждений.** Подтверждённые инструменты сохраняются
  между кадрами и перезапусками; добавлены образцы значков Crown и Claws.
  Обновление прогресса сохраняет кнопки оверлея и не теряет нажатие мыши.
  Лишние иконки из-за шумной сегментации больше не отменяют These are right.
  Подтверждение снимается при новом забеге, новом выборе или ручном изменении предметов.
- **Без повторного старта на той же доске.** Повторный кадр и подтверждение
  инструментов сохраняют незавершённый расчёт и его выборки. При готовом OCR
  счётчик цели применяется до запуска расчёта. Загрузка OCR остаётся фоновой.
  Обновления интерфейса не сбрасывают совместимый кэш. Перенос новых правил
  и оценок инструментов в local.21 использует новый кэш, чтобы не выдавать
  старые оценки. Подтверждения инструментов сохраняются отдельно.

## Измеренный прирост

В контрольном замере **local.27** на двух сохранённых игровых кадрах обработка трёх
наблюдений готовности заняла **811 мс вместо 1 395 мс** у local.26. Первые два
наблюдения теперь проверяют пиксели; третье распознаёт поле и доступные кнопки.
Это затраты на проверку, без интервалов между наблюдениями, анимаций игры и расчёта
совета. Один последовательный замер не доказывает такой же прирост всего хода или
профита в час. [Отчёт проверки](tools/results/tartarus-reader-27-20261023-validation.json).

В **local.26** Rust/WASM сравнен с JS-реализацией **той же стратегии** внутри
готового Electron 44.5.1, Ryzen 5 3600. Один воркер, пять измерений в чередующемся
порядке, медианы; по 64 полных проигрывания оставшейся партии на каждый вариант:

| Позиция | JavaScript | Rust/WASM | Ускорение |
| --- | ---: | ---: | ---: |
| Стартовый выбор инструмента | 420 мс | 76 мс | **5,56×** |
| Патруль первого дня | 399 мс | 66 мс | **6,03×** |
| Заполненная доска со сложным набором инструментов | 806 мс | 168 мс | **4,80×** |
| Cage Fight | 366 мс | 49 мс | **7,40×** |
| Подарки Opulence | 785 мс | 129 мс | **6,10×** |

Выборки и ранжирование совпали. Измерение включает инициализацию задания,
порции расчёта, обмен с Rust и сводку результата. Захват, OCR, анимации игры,
холодная компиляция WASM и параллельное планирование сюда не входят; фоновая
нагрузка ПК не фиксировалась. Это ускорение ядра, а не замер профита в час.
Условия и исходные измерения: [отчёт Rust](tools/results/tartarus-rust-20261023-validation.json).

Отдельно исправлена модель будущих цепочек: волк с Fanged Guillotine теперь
учитывает еду меньшей редкости. Начальный перенос сверялся без изменений
стратегии; исправление затем проверялось отдельно на 16 384 парных забегах.
В среднем сдвиг небольшой, для большинства наборов укладывается в погрешность:
[проверка стратегии](tools/results/tartarus-rust-quality-20261023.json).

В **local.24** распознавание дополнительно сравнено с **local.23** на двух
сохранённых кадрах 2560×1440 в настоящем Electron 44.5.1, Ryzen 5 3600.
Версии запускались поочерёдно: один прогрев и три измерения, ниже медианы.
Полный поиск и повторное чтение с уже найденным полем измерялись отдельно;
результаты распознавания совпали, кроме самого времени выполнения.

| Этап | local.23 | local.24 | Ускорение |
| --- | ---: | ---: | ---: |
| Полный поиск и чтение, кадр A | 932 мс | 401 мс | **2,32×** |
| Полный поиск и чтение, кадр B | 949 мс | 512 мс | **1,85×** |
| Повтор того же кадра A с найденным полем | 155 мс | 120 мс | **1,29×** |
| Повтор того же кадра B с найденным полем | 233 мс | 178 мс | **1,31×** |

Повтор неизменного кадра не равен переходу между игровыми ходами. Эти числа
не включают захват, ожидание анимации и Монте-Карло; фоновая нагрузка ПК не
фиксировалась. Передача данных проверки готовности проверена отдельно:
используется только тот же принятый снимок, другой снимок читается заново.
Исходники, хэши и условия: [отчёт local.24](tools/results/tartarus-reader-20261023-validation.json).

Множители разных этапов нельзя перемножать. Ускорение не получено за счёт
уменьшения рабочего бюджета Монте-Карло.

## Запуск оптимизированного режима

Windows x64. Скачайте готовую сборку из
[Releases](https://github.com/milkmiraclework-alt/tartarus-overlay-optimized/releases/latest):

- `Tartarus-Optimized-Portable-…-x64.exe` — запуск без установки.
- `Tartarus-Optimized-Setup-…-x64.exe` — обычная установка с ярлыком.

Закройте прежний оверлей через трей и запустите скачанный файл. Установка
оверлея автора, Node.js и Rust не нужны. Игра должна работать в оконном режиме
или без рамки. Настройки, подтверждения инструментов и кэш остаются в прежнем
профиле `%APPDATA%\Tartarus Overlay`.

Для самостоятельной сборки из исходников нужны Node.js 22.12+ с npm:

```powershell
.\Build-Standalone.cmd
```

Результат появится в `desktop/dist`. После сборки `.\Start-Local-Overlay.cmd`
запускает готовый EXE. Проверки выполняются с изолированным профилем и тестовым
окном, без управления реальной игрой. Подробности: [desktop/README.md](desktop/README.md).
Проверки готового Portable и автономного OCR:
[отчёт автономной сборки](tools/results/tartarus-standalone-20261023-validation.json).

## Как проверить прирост

Для проверок нужен Node.js 22+. Готовый Rust/WASM уже в репозитории.
Точная сверка использует текущую JS-реализацию тех же правил и стратегии:

```powershell
node tools/rust-solver-manifest.js
node tools/rust-solver-check.js --wasm
node tools/rust-worker-check.js
node tools/solver-check.js
node tools/overlay-check.js --standalone "desktop/dist/win-unpacked/Tartarus Optimized.exe" --rust-bench
node tools/overlay-check.js --standalone "desktop/dist/win-unpacked/Tartarus Optimized.exe" --forecast-only
node tools/calculation-check.js
node tools/worker-budget-check.js
node tools/overlay-check.js --instruments-only
node tools/overlay-check.js --contracts-only
node tools/upstream-check.js
node tools/desktop-upstream-check.js
node tools/scan-panel-check.js
```

Сверка с прежней стратегией и исправления локальных формул оцениваются отдельно:
изменение стратегии не обязано сохранять прежние рекомендации. Начальный точный
перенос зафиксирован в `tools/results/tartarus-rust-port-baseline-20261023.json`.
Для пересборки Rust-модуля нужны Rust с `wasm32-unknown-unknown` и команда
`powershell -File tools/build-rust-solver.ps1`; для запуска готового приложения они не нужны.
Личные игровые скриншоты и профили в форк не включены.
Проверки сравнивают полные результаты распознавания, решения, выборки
Монте-Карло, ранжирование, работу кэша и остановку фоновых задач.
